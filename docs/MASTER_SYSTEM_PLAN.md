# BICS master system plan — Phase 1

## Current state

Repository audit on 11 August 2026 found an initialized Git repository on `master` with no commits and no working-tree source files. There is no `package.json`, framework, route tree, component library, styles, assets, configuration, form implementation, SEO implementation, demo-mode implementation, or runnable build. Therefore no existing project could be started, and no technical debt or build health assessment applies yet.

## What should be kept

- The empty repository: it is a clean starting point for an intentionally small, maintainable system.
- The supplied product specification as the operating brief.

## What should be changed

Nothing in Phase 1. Phase 2 should introduce a framework only after selecting deployment and rendering requirements. The recommended default is a current stable Next.js + TypeScript application deployed to Vercel because it supports content routes, metadata, image optimization, server-side lead handling, and campaign landing pages in one deployable unit.

## Reusable architecture

Use a config-first application boundary:

```
src/
  app/                    # routes, metadata, API handlers
  components/             # reusable page sections and primitives
  config/site.ts          # typed brand, business, content, integrations, modes
  lib/                    # lead validation, analytics, SEO, integrations
  styles/                 # tokens and global styles
public/assets/            # client-replaceable media
docs/
```

`site.ts` owns brand, business, contact, navigation, hero, projects, services, process, project fit, inquiry, SEO, analytics, integrations, theme, `demoMode`, and `conceptMode`. Components consume that data and must not carry client names, URLs, or tracking IDs inline.

## Design system

- Light-first configurable tokens: canvas `#EFEAE1`, surface `#F6F2EA`, ink `#292621`, muted ink `#756F66`, terracotta `#A76542`, hairline `rgba(41,38,33,.16)`.
- One contemporary, freely licensed sans family such as Manrope, Hanken Grotesk, or Inter Tight; choose after prototype comparison. No default display serif/italic formula.
- Photography-led editorial grids, quiet metadata, hairlines, asymmetric but readable hero composition, and natural stacked mobile sequences.
- Semantic HTML, skip link, visible focus, reduced-motion support, descriptive alt text, stable image proportions, and 44px minimum touch targets.

## Conversion system

The homepage should guide visitors through: premium project evidence → service clarity → process → project fit → structured inquiry. Use one consistent primary CTA (“Begin a Project”), plus “View Projects” in the hero. Place primary CTA only in the header, hero, post-project, project-fit, and final CTA. Avoid card-heavy SaaS patterns and generic contact forms.

## Inquiry system

Build `/inquire` as an accessible five-step progressive form: contact; property; project; fit (budget, start date, decision maker); detail/source. Persist progress only in-browser while completing, validate per step, include a honeypot, clear errors, and a calm review/success state. In demo or concept mode, submission is simulated and clearly disclosed.

## CRM architecture

In production, a server-only `POST /api/lead` validates and normalizes the payload, verifies allowed origin, applies basic abuse controls, and sends only server-side to `MAKE_WEBHOOK_URL`. Make then maps fields into a client-owned HubSpot pipeline and Brevo/Calendly workflow. Define an adapter interface so providers can change without altering UI. Never expose webhook URLs or secrets in client bundles.

## Ads architecture

Support config-defined campaign pages (not autogenerated city pages), UTM capture, source attribution, and typed events. Keep Meta Pixel, future Conversions API, GA4, and future Google Ads configuration centrally controlled and disabled in demo/concept mode. Establish a consent strategy before enabling production tracking.

## SEO architecture

Every production route needs distinct title, description, canonical, Open Graph data, a single H1, logical headings, internal links, and optimized images. Generate sitemap and robots rules. Enable truthful JSON-LD (Organization/LocalBusiness, Service, Person, BreadcrumbList) only when production facts exist. Build service-area pages only for genuine markets, with useful local content and relevant work—never city-page automation.

## Outreach concept mode

`conceptMode` supplies prospect name and disclaimer, forces `noindex`, disables analytics and real lead delivery, and prevents any statement of affiliation. Its purpose is a private concept URL with a fast asset/config swap, not a public claim of client work.

## Implementation phases

1. **Complete:** Audit and research; create these documents.
2. Select stack, scaffold typed config, tokens, root layout, modes, and route shell.
3. Build the homepage and reusable project, service, studio, and process pages.
4. Build and test the multi-step inquiry interface.
5. Implement SEO metadata, sitemap, robots, structured-data utilities, and local-content route support.
6. Add hardened lead endpoint and provider adapters with environment documentation.
7. Add consent-aware analytics/ad event layer and UTM attribution.
8. Add outreach concept mode and QA.
9. Finish operational docs, accessibility/mobile/performance checks, and deployment handover.

## Risks

- High-quality licensed photography and complete project facts are prerequisites for a premium result.
- Conversion cannot be proven from inspiration alone; use production analytics and qualified-lead feedback to iterate.
- Legal/privacy requirements, consent tooling, CRM field ownership, and email automation need client-specific decisions before launch.
- Image-heavy pages can miss performance targets without asset sizing, modern formats, and editorial restraint.
- An unselected framework/deployment target is currently the only implementation blocker; no code exists to extend.

## Dependencies

- Confirmed stack and deployment owner (recommended: Next.js, TypeScript, Vercel).
- Client-owned domain, HubSpot, Make, Brevo, Calendly, analytics, Search Console, and ad accounts as applicable.
- Production environment variables: `MAKE_WEBHOOK_URL`, `ALLOWED_SITE_ORIGIN`, and provider keys only where required.
- Licensed client assets, approved service areas, factual business details, privacy policy/terms, and consent requirements.

## Phase 2 decision gate

Before scaffolding, confirm whether this empty repository is intentionally the BICS master repository and approve the recommended Next.js/Vercel baseline (or provide an existing application/repository to audit instead).
